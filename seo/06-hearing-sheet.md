# クライアント確認シート（最優先で回収する）

## なぜこれが最優先か

AIMARKS・SOKUSEN とも、一般の検索で拾える公開情報がほとんどない。
つまり**一次情報をもらわないと、事実を書けない**。

指名キーワードの記事は、そのサービスを実際に検討している人が読む。
料金や支援範囲を推測で書けば、読者は公式サイトや商談ですぐ食い違いに気づく。
その時点で記事も、記事を出している側も、信用を落とす。SEO以前の問題として、
**確認が取れていない事実は書かない**を徹底する。

このシートを埋めてもらえれば、20本すべてを事実ベースで書き切れる。
逆にここが埋まらない項目は、記事側でその話題を扱わないか、
「公式サイトでご確認ください」と誘導する構成に切り替える。

- [ ] 記事の公開先ドメイン（後述「D」参照）

## B. AIMARKS

- [ ] 一言でのサービス定義（「〜な企業向けに〜を提供するサービス」）
- [ ] 提供サービスの一覧と、それぞれの支援範囲
- [ ] 営業代行の具体的な業務範囲（リスト作成／アポ獲得／商談同席／クロージングはどこまで）
- [ ] AIをどこにどう使っているのか（技術的な説明の粒度も含めて）
- [ ] 料金体系（固定／成果報酬／ハイブリッド）と、公開してよい価格レンジ
- [ ] 最低契約期間・契約単位
- [ ] 導入までの流れ（問い合わせ→商談→契約→稼働までの日数感）
- [ ] 導入事例（社名を出せるもの／匿名でよいもの／出せる数値）
- [ ] 対応できる業界・商材、逆に対応が難しいケース
- [ ] よくある質問（営業担当が実際に聞かれるTOP10）
- [ ] 採用の有無・募集職種（09番の記事を書く場合）

- [ ] 受講料と支払い方法（分割の有無）
- [ ] 返金・保証制度の有無と条件

## D. 公開先・技術面（ここが決まらないと着手できない）

- [ ] 記事はどこに公開するか

      - 専用の新規ドメイン
      - note / はてなブログ等の外部プラットフォーム
- [ ] CMSは何か（WordPress / 独自 / その他）、投稿権限をもらえるか
- [ ] Search Consoleへのアクセス権をもらえるか（**STEP 2の報告に必須**）
- [ ] Googleアナリティクス（GA4）のアクセス権
- [ ] LINE公式アカウントの友だち追加URL
- [ ] 記事ごとの流入計測方法（UTMを付けたURLを使ってよいか、
      LINE側で流入元を判別できるか）
- [ ] 公開前にクライアント確認を挟むか、こちらの判断で公開してよいか

## E. 契約条件（着手前に文面で残す）

- [ ] STEP 1（20記事の制作・公開）の報酬の有無と金額・支払時期
- [ ] 成果報酬の定義：「成約」とは何をもって成立とするか
- [ ] 成果報酬の単価と支払サイクル
- [ ] 成果の計測方法と、その数値を誰がどう共有するか
- [ ] 記事の著作権の帰属、契約終了後の記事の扱い
- [ ] 修正対応の範囲と回数

> **注意**：募集要項の書き方だと、STEP 1の20記事は成果報酬前提で、固定報酬の記載がない。
> 20本の記事制作は、キーワード設計から公開まで含めれば相当な工数になる。
> 着手前に「STEP 1の扱い（固定報酬の有無）」と「成果報酬の成立条件・単価」を
> 文面で確定させておくこと。ここを曖昧にしたまま20本書くのがいちばん危ない。
