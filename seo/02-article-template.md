# 記事構成テンプレート

20本すべてこの型で書く。型を固定すると、執筆速度が上がるだけでなく、
内部リンクとCTAの位置がそろって計測しやすくなる。

---

## メタ情報（記事上部に管理用として持つ）

```
主KW      :
サブKW    :
検索意図  : （知りたい／比較したい／申し込みたい のどれか）
読者の状態: （何を知っていて、何が分からなくて、次に何をするか）
タイトル  : （全角30字前後、主KWは左寄せ）
ディスクリプション: （全角110〜120字）
URLスラッグ: 半角英数・ハイフン区切り（例 /aimarks-sales-outsourcing/）
想定文字数: 3,000〜5,000字（指名複合KWは2,500字でも可）
内部リンク: 出す先3〜5本 / 受ける元
CTA位置   : 導入直後 / 中盤 / 記事末
```

---

## 本文構成

### 1. リード（200〜300字）

- 1行目で結論。「〜とは、{{一言定義}}です。」から始める
- 「この記事で分かること」を3点、箇条書き
- 誰向けの記事かを明示（「依頼を検討している企業の担当者向け」など）
- 冒頭に長い自己紹介や前置きを入れない。指名検索の読者はせっかちで、
  答えが出てこないと即戻る

### 2. 結論ブロック（H2：〜とは？を先に答える）

- 検索意図に対する答えを、スクロールなしで読める位置に置く
- 表か箇条書きで要点を3〜5行に圧縮
- ここだけ読んで離脱しても損させない。むしろ滞在の質が上がる

### 3. 詳細ブロック（H2×3〜5、各H2にH3を2〜3）

- H2は「読者の質問文」に近い形にする（「料金はいくら？」「どこまでやってくれる？」）
- 1つのH2に1つの論点。詰め込まない
- 数字・固有名詞・手順は必ず一次情報から。**推測で書かない**
- 各H2の末尾に1行まとめを置くと、流し読み層に刺さる

### 4. よくある質問（H2：よくある質問）

- Q&Aを5〜7個。サジェスト・共起語をここで回収する
- FAQ構造化データ（`FAQPage`）を入れる。リッチリザルトに出れば指名検索での面積が増える

### 5. まとめ＋CTA（H2）

- 記事の結論を3行で再掲
- そのうえでLINE導線へ。「詳しい料金を知りたい方はLINEで」など、
  **記事内容の続き**としてつなぐ。唐突なCTAは踏まれない

---

## CTAの書き方（STEP 3の成果報酬に直結）

CTAは3か所。文言はすべて記事のテーマに合わせて変える。

| 位置 | 形式 | 文言の方向性 |
| --- | --- | --- |
| リード直後 | テキストリンク1行 | 「先に個別の条件を聞きたい方はこちら」 |
| 中盤（料金・事例の直後） | ボタン | 「自社のケースで見積もりを相談する」 |
| 記事末 | ボタン＋補足 | 「無料相談はLINEから。しつこい営業はありません」 |

- 記事ごとにUTMパラメータを変え、どの記事からの登録か測れるようにする
  例：`?utm_source=seo&utm_medium=article&utm_campaign=aimarks&utm_content=04-price`
- 「登録すると何が起きるか」を1行必ず添える（誰から何が届くのか）。
  不明瞭なCTAは登録率が落ちるうえ、質の低いリードが増えて成約率も下がる

---

## 書くときの禁止事項

- 確認が取れていない料金・実績・社数・受講者数を書く
- 「業界No.1」「必ず成果が出る」など、根拠を示せない最上級・断定表現
- 公式サイトの文章のコピー
- 他社の悪口で相対的に持ち上げる書き方（比較記事でも事実ベースで並べる）
- AIが書いたままの、同じ文末が続く文章。読点と文末を意図的にばらす

## 構造化データ

- 全記事：`Article`（`headline` / `datePublished` / `dateModified` / `author` / `publisher`）
- FAQがある記事：`FAQPage`
- 手順を扱う記事（19番など）：`HowTo`
- 会社を扱う記事（08番）：`Organization`
