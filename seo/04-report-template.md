# STEP 2 成果報告テンプレート

20記事の公開完了後に提出する報告書の型。
「書いて終わり」ではなく数値まで見る案件なので、**言い訳を書かず事実を並べる**のが基本。
順位が付いていない記事も、正直にそう書く。付いていない理由の仮説と次アクションまで書けば、
むしろ継続の判断材料として価値が出る。

---

## 1. サマリー

```
報告日      : YYYY/MM/DD
公開本数    : 20 / 20 本
公開期間    : YYYY/MM/DD 〜 YYYY/MM/DD
計測日      : YYYY/MM/DD（順位・SCデータの取得日）
計測環境    : シークレットウィンドウ / 地域=東京 / デバイス=PC・スマホ両方
10位以内    : ○本
30位以内    : ○本
未順位      : ○本
合計表示回数: ○○ 回（Search Console／公開日〜計測日）
合計クリック: ○○ 回
LINE登録    : ○ 件（UTM別内訳は §5）
```

| 01 |  |  |  |  |  |  |  |  |  |  |
| … |  |  |  |  |  |  |  |  |  |  |

※ 順位はGoogle検索での実測、平均掲載順位はSearch Console値。両方載せると
　「実測は3位だがSC平均は8位」のような差が見え、改善の手がかりになる。

## 3. スクリーンショット

記事ごとに以下を撮る。ファイル名は `screenshots/{記事番号}-{KW}-{YYYYMMDD}.png`。

- [ ] 検索結果画面（検索窓のKWと自記事が同一画面に写っていること）
- [ ] Search Console の「検索パフォーマンス > ページ」でそのURLをフィルタした画面
- [ ] 撮影日が分かる状態（日時表示 or 撮影日をファイル名に）

撮り方の注意：シークレットウィンドウで撮る。ログイン状態やパーソナライズが入った順位は
証跡にならない。

## 4. Search Console データ

添付するもの：

- [ ] 検索パフォーマンスのCSVエクスポート（クエリ別 / ページ別、期間＝公開日〜計測日）
- [ ] インデックス登録状況（20本中いくつがインデックスされているか）
- [ ] 主要クエリ上位20件（表示回数順）

ここで確認したい観点：

- 指名KWで表示されているか（＝そもそも指名検索の土俵に乗れているか）
- 想定していなかったクエリで拾えているものはないか（次の記事ネタになる）
- 表示回数はあるのにCTRが低いページ（＝タイトル・ディスクリプションの改善余地）

## 6. 所感と次アクション

以下の3点だけを、各3〜5行で。

1. **効いたこと** — どのタイプの記事が伸びたか、事実ベースで
2. **効かなかったこと／課題** — 順位が付かなかった記事とその要因の仮説
3. **次にやるべきこと** — 追加すべきKW、リライト対象、導線の改善案

## 提出形式

- 本文：スプレッドシート（§2, §5）＋ドキュメント（§1, §6）
- 添付：スクリーンショット一式、Search ConsoleのCSV
- 共有前に、URLがすべて開けるか・画像が抜けていないかを自分で一度確認する
